# Day 10 · 工具名相同，为什么要回填两次？

[上一天：谁控制循环](../day09/README.md) · [下一天：谁控制计划](../day11/README.md)

假设应用注册了一个 `lookup_order`，模型一次回复便提出两个请求：`c1` 查订单 A，`c2` 查订单 B。此时有**一个工具、两个调用、零条查询结果**。模型产生的是调用请求，订单数据尚未被读取。

## 工具的名字回答「用谁」，调用 ID 回答「回给谁」

先读 [摘抄 1：从名字到本地工具对象](01_dispatch.md)。`ToolCollection` 同时服务两个读者：模型拿到 `to_params()` 生成的描述，用来选择工具；应用持有 `tool_map`，用来取出真正可执行的对象。类似 Java 根据字符串键在 `Map` 里取处理器。这个类比止于本地分发：模型并不持有该处理器的引用，也不能直接调用它。

再读 [摘抄 2：串行执行与按 ID 回填](02_tool_messages.md)。只看与工具有关的消息，这一次交互有三个时刻：

| 时刻 | 消息历史中已有的记录 | 此时还不知道什么 |
|---|---|---|
| 模型刚回复 | 一条 `assistant` 消息，内含 `c1(A)` 和 `c2(B)` | 两笔订单的结果都未知。 |
| 第一次 `await` 返回并回填 | 多了一条 `tool(c1, 结果 A)` | B 还没执行。`await` 写在 `for` 内，不会自动并发。 |
| 第二次回填后 | 又多了一条 `tool(c2, 结果 B)` | 是否需要下一步，由外层循环及下一次决策决定。 |

如果用工具名作为结果的唯一键，两项都叫 `lookup_order`，第二项就可能覆盖第一项。用调用 ID 配对，即使模型两次查的是**同一笔**订单，也能区分两次尝试。

## 反例：有一条 `tool` 消息，查询却没发生

假设 `c1` 的参数不是合法 JSON。[`execute_tool` 的错误分支](https://github.com/FoundationAgents/OpenManus/blob/99eea8e/app/agent/toolcall.py#L174-L216)在真正分发前就返回错误文字。`act()` 把这段文字作为 `c1` 的结果记录，随后仍可处理 `c2`。因此不能数两条 `tool` 消息就报告「查到了两笔订单」；先按 ID 找到结果，再看内容属于数据还是错误。

同样，**一次模型回复结束也不等于 Agent 循环结束**。例如执行终止工具后，[特殊工具处理](https://github.com/FoundationAgents/OpenManus/blob/99eea8e/app/agent/toolcall.py#L218-L235)设置 `FINISHED`；Day 9 的外层循环在再次检查条件时才停。这个赋值不会从当前工具列表中间跳出。
